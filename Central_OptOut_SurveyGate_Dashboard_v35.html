Link and email settings

Microsoft Outlook (sign in and send): click Sign in with Microsoft and choose your Outlook account. The emails then go out from that mailbox through Microsoft, in batches, with no other service involved and no files downloaded. Choose "Save to my Outlook Drafts" instead if you want to edit each email in Outlook before sending it. One-time setup, by you or IT: in Microsoft Entra (portal.azure.com) go to App registrations, New registration, choose "Accounts in any organizational directory and personal Microsoft accounts" (needed for outlook.com addresses), add a Single-page application redirect URI exactly as shown above, then under API permissions add the Microsoft Graph delegated permission Mail.Send (and Mail.ReadWrite for drafts). Paste the Application (client) ID here. Use Account type "common" for outlook.com addresses, or your tenant ID for a work account (an administrator may need to approve the permission). The page must be opened from a web address such as http://localhost, not as a file; a quick way is to run python -m http.server 8000 in the folder holding this file and open http://localhost:8000/. You stay signed in for this session only. The email is sent from the signed-in mailbox, so the From box follows it.

Open an Outlook window: opens a compose window in Outlook.com or Outlook on the web with a plain-text version for you to edit and send yourself, one email at a time. EmailJS: connect the Outlook mailbox as an Outlook service, then create a template with To = {{to_email}}, Subject = {{subject}} and body = {{{html}}} (three braces). Webhook: the dashboard POSTs JSON (from, fromName, to, toName, subject, html, participantId) to your URL, for example a Power Automate HTTP trigger followed by Send an email (V2). Note: the From address is used as the From value for EmailJS, webhook and draft (.eml) sends. With Microsoft sign-in or Outlook, the message is sent from the account you sign in with, because Microsoft only allows another sender if that account has Send As rights. Email addresses and names pass through the service you choose, so confirm it meets your privacy rules.

A record of every survey answer, Opt-Out answer and email, newest first. History is stored in this browser: export it for a permanent copy.

Stored data and backup

Opt-out list, audit trail, sharing status, templates and settings are saved in this browser and survive a refresh. Uploaded participant and survey files are not stored: drop them in again after a refresh and the saved history re-attaches by participant ID. Download a backup regularly, because clearing browser data deletes everything.

Map your CSV headings

The headings in this file do not match automatically. Match each field the participant CSV uses (PARTICIPANT_ID, EMAIL_ADDRESS, PARTICIPANT_NAME and CUSTOM_FIELD1 to CUSTOM_FIELD5) to a column in your file. Fields marked * are required. Any column you leave out of the mapping is still kept as an extra field.
